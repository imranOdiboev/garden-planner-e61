# Корпус и воспроизводимая оценка

Все тексты **синтетические**, все числа вымышлены. Корпус служит проверкой метода, а не нормативным источником. Эталон — `dataset.json`; человекочитаемые копии — `texts/T01.txt` … `T10.txt`.

| Текст | Что проверяет |
|---|---|
| T01 | Расстояние и несущественный фрагмент |
| T02 | Условие материала и исключение |
| T03 | Дубль при обмене объектов и переводе сантиметров в метры |
| T04 | Несовместимые нижняя/верхняя границы |
| T05 | Разные условия wood/stone; противоречия нет |
| T06 | Две совместимые нижние границы; разные числа |
| T07 | Числовое условие высоты и расстояние до границы |
| T08 | Только несущественная информация; правил нет |
| T09 | Логическое условие негерметичности |
| T10 | Запрет, преобразуемый в ограничение расстояния |

Каждый пример хранит исходный текст, признак синтетичности, источник, эталонные правила (включая условия/исключения) и ожидаемые отношения между правилами. Заголовок синтетичности в TXT предназначен для человека; CLI использует текст поля `text` из JSON. Это важно для точного воспроизведения входа.

## Запуск

Установите зависимости проекта и запустите Ollama с выбранной моделью. FastAPI-сервер для CLI не требуется.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m evaluation.evaluate --model qwen2.5:3b --repeats 1 --seed 42 --temperature 0 --num-ctx 16384 --num-predict 4096
```

Быстрый предварительный запуск: `--cases T01 T02`. Для оценки повторяемости используйте `--repeats 3` и сохраните все ответы. Порядок двух конвейеров чередуется между повторами; время первого вызова может включать загрузку модели. В trace записаны длительность загрузки, общее время Ollama и количество токенов, если сервер их вернул.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m evaluation.evaluate --prepare-only
```

Эта команда только создаёт протокол: `status=not_run`, `metrics=null`. Если модель недоступна при обычном запуске, CLI тоже записывает `not_run` с фактической причиной и не подставляет ответы/метрики. Коды завершения: 0 — выполнено/подготовлено, 1 — частичный эксперимент, 2 — модель недоступна.

По умолчанию результаты пишутся в `evaluation/results`; другая папка задаётся `--output`. Повторный запуск с тем же набором имён перезаписывает соответствующие файлы, поэтому сохраняйте отдельные папки для разных моделей/экспериментов.

## Два сравниваемых порядка

- `filter_first`: фрагменты → сущности → связи/правила → проверка совместимости.
- `entities_first`: сущности → фрагменты → связи/правила → проверка совместимости.

Параметры одинаковы. Модель/digest, версия Ollama, версия промпта, seed, temperature, num_ctx, num_predict, Python, платформа и SHA-256 корпуса записываются в протокол. Каждый вызов сохраняет ответ этапа, запрос и ошибку при наличии. Эталоны не передаются модели.

## Метрики

`precision = TP / (TP + FP)`, `recall = TP / (TP + FN)`, `F1 = 2TP / (2TP + FP + FN)`. Сводка считает micro-показатели по всем **завершённым** примерам, с обязательным числом завершённых/запланированных запусков и ошибок. При неполном покрытии сравнение качества интерпретируется осторожно. Пустой знаменатель — `null`/тире, а не 100 %.

| Метрика | Единица сопоставления |
|---|---|
| Сущности объектов | Множество нормализованных типов `kind=object` из нейросетевого этапа, эталон из типов правил |
| Значения | Объекты/параметр/единица/область, оператор, число после перевода в метры; мультимножество |
| Условия и исключения | Контекст правила, роль a/b, поле, оператор, скалярное значение и вид condition/exception |
| Противоречия | Пары правил с меткой conflict после однозначного сопоставления кандидатов эталону |
| Дубли | Пары с меткой duplicate после такого же сопоставления |

Сущности требований/запретов сохраняются в trace и доступны для качественного разбора, но не имеют отдельного F1 в маленьком корпусе. Число, извлечённое для неправильной пары объектов, не засчитывается как правильное значение. Условия с другой ролью или исключение, ошибочно записанное как условие, также штрафуются. Непредусмотренный конфликт в T05/T06 увеличивает FP. Сомнительные отношения review подсчитываются отдельно и не приравниваются к доказанному конфликту. Удаление несущественных фрагментов фиксируется дополнительным счётчиком.

`comparison.md` появляется только после реальных запусков. Он сравнивает показатели двух порядков и среднее время. Не следует делать вывод о превосходстве порядка на десяти синтетических текстах без расширения корпуса и анализа ошибок.

## Статус поставки

Ollama в среде разработки недоступна. Подготовка протокола и отказ при отсутствии модели проверены; **нейросетевое извлечение и сравнение качества не выполнены**. Метрик модели в поставке нет. Модульные тесты на тестовых транспортных ответах не включаются в экспериментальные результаты.
