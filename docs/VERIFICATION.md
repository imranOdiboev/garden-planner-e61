# Проверки и подтверждённые результаты

## Основания

Документ разделяет автоматические тесты, сохранённую HTTP-проверку, проверки интерфейса и статус нейросетевого эксперимента. Числа приведены по указанным записям. Они не подтверждают соответствие строительным нормативам или качество языковой модели.

Версии проверенного окружения: Python 3.12.14, FastAPI 0.143.0, Uvicorn 0.54.0, Pydantic 2.14.1. Зафиксированные зависимости находятся в [requirements-lock.txt](../requirements-lock.txt). В протоколе оценки указана Windows 11.

## Автоматические тесты

Команда из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

Запуск 14 октября 2026 года завершился с результатом **54 теста, OK**, без ошибок и пропусков. Полный вывод — [unit-test-output.txt](unit-test-output.txt). Используется стандартный `unittest`.

| Модуль | Проверяемые свойства |
|---|---|
| `test_core.py` | Расстояния, поворот, пересечения, вогнутые границы, JSON, условия, исключения, единицы и отношения правил |
| `test_api_logic.py` | Запись и подтверждение базы, обновление ID, блокировка дублей и конфликтов, импорт и измерение |
| `test_neural.py` | Запрос Ollama, JSON Schema, неверные ответы, обрезание, цитаты, порядки этапов и состояние кандидатов |
| `test_evaluation.py` | TP/FP/FN, F1, пустые эталоны, единицы и штраф за ложный конфликт |

Аналитические случаи включают расстояние 7 м между прямоугольниками 4 × 2 м в центре (0,0) и 2 × 2 м в (10,0). Поворот первого на 90° даёт 8 м. Для квадрата 2 × 2 м под 45° и такого же квадрата в (5,0) проверяется `4 − √2` м. Проверяется также вогнутая граница, где вершины объекта внутри, а ребро выходит через выемку.

## Сохранённая HTTP-проверка

Источник — [api-verification.json](api-verification.json). Запись имеет `status: passed` и содержит восемь сценариев:

1. Чтение статуса сервера.
2. Загрузка и проверка JSON без потери данных.
3. Отклонение отрицательного размера.
4. Отклонение запроса с другим Origin.
5. Измерение от дома до границы: 7 м.
6. Проверка трёх статусов результатов.
7. Чтение статуса Ollama.
8. Ответ HTTP 503 при недоступной модели.

Для повторения нужен работающий сервер на стандартном порте:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\smoke_api.py
```

Команда перезаписывает `docs/api-verification.json`. Сохранённая запись использована как результат предыдущей HTTP-проверки; при редактировании документации она не изменялась.

Результаты исходного плана с шестью синтетическими правилами:

| Статус | Число результатов |
|---|---:|
| Нарушение | 2 |
| Соответствует | 15 |
| Недостаточно данных | 2 |

Счётчики объединяют геометрические и применимые учебные проверки. Они не являются метриками нейросетевого извлечения.

## Проверки интерфейса

При проверке через браузер были выполнены следующие действия:

| Сценарий | Наблюдавшийся результат |
|---|---|
| Выбор и изменение объекта | Название «Дом — проверка» и угол 45° применены |
| Измерение до границы | После поворота дома отображено 5,636 м |
| Сохранение и загрузка JSON | Название и угол восстановлены |
| Изменение участка | X третьей вершины изменён с 30 на 28; площадь с 1200 на 1160 м² |
| Изменение коммуникации | X второй точки водоснабжения изменён с 10 на 11 |
| Объект у соседа | Куст добавлен в (−9,9), перемещён в (−5,12) и удалён |
| База правил | Просмотр, проверка связей и подтверждение учебного правила выполнены |
| TXT и неверный JSON | Текст UTF-8 загружен; план без участков отклонён |
| Недоступная модель | Сообщение об ошибке показано; кандидаты не созданы |
| Проверка исходного примера | Отображены результаты 2/15/2 и переход к проблемному объекту |

## Нейросетевой эксперимент

Источник — [evaluation/results/status.json](../evaluation/results/status.json). В нём указаны `status: not_run`, `metrics: null` и недоступность сервиса или модели. Зафиксированы предполагаемая модель `qwen2.5:3b`, параметры, оба порядка, десять текстов и контрольная сумма корпуса.

Сервис не был доступен для извлечения. Ответов модели, экспериментальных F1 и измерений времени обработки нет. Тестовые транспортные ответы из `test_neural.py` проверяют программную логику и не включаются в экспериментальные результаты.

## Непроверенные части

- Извлечение и подтверждение кандидатов после успешного вызова установленной модели.
- Качество двух порядков на синтетическом и проверенном нормативном корпусах.
- Применение базы, подтверждённой по нормативным источникам.
- Установка и приёмка на независимом компьютере Windows.

Порядок выполнения этих работ приведён в [отчёте](REPORT_DRAFT.md#8-работы-для-завершения-задания-е61).
