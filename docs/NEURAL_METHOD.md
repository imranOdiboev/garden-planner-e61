# Нейросетевой метод извлечения правил

## Назначение и статус

Модуль преобразует русский текст в кандидаты правил. Он извлекает объекты, требования, запреты, условия и исключения. Семантические этапы выполняет языковая модель через локальный API Ollama. Проверка структуры и совместимости выполняется серверным алгоритмом.

Клиент Ollama, оба порядка этапов и сценарий оценки реализованы. Проверены транспортные запросы и обработка ответов на тестовых данных. **Извлечение установленной моделью и сравнение качества двух порядков не выполнены.** Сохранённый [протокол](../evaluation/results/status.json) имеет статус `not_run` и `metrics: null`.

## Подключение

Приложение использует `POST /api/chat`, `stream: false` и JSON Schema в поле `format`. Запрос выполняется через стандартный `urllib`. В промпт также включается схема ответа.

Документация интерфейса Ollama: [Chat API](https://docs.ollama.com/api/chat), [Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs). Эти ссылки описывают интеграцию, но не являются источниками строительных правил.

| Настройка | Значение по умолчанию | Назначение |
|---|---|---|
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Адрес сервиса |
| `OLLAMA_TIMEOUT` | `180` | Тайм-аут одного вызова, секунды |

Настройки задаются перед запуском сервера:

```powershell
$env:OLLAMA_URL = 'http://127.0.0.1:11434'
$env:OLLAMA_TIMEOUT = '300'
.\run.bat
```

Допускаются локальные HTTP-адреса с узлами `localhost`, `127.0.0.1` или `::1`. Установка сервиса и модели описана в [README](../README.md#5-настройка-нейросетевого-модуля).

## Входные данные и параметры

Запрос содержит `text`, `source`, `model`, `order`, `seed`, `temperature`, `num_ctx`, `num_predict`. Максимальная длина текста — 18 000 символов. TXT должен иметь кодировку UTF-8. Источник задаётся пользователем в формате [RULES.md](RULES.md#источник-и-активация).

| Параметр | По умолчанию | Допустимые значения |
|---|---|---|
| `model` | `qwen2.5:3b` | Имя установленной модели |
| `order` | `filter_first` | `filter_first`, `entities_first` |
| `seed` | `42` | От 0 до 2 147 483 647 |
| `temperature` | `0` | От 0 до 1 |
| `num_ctx` | `16384` | От 4096 до 32768 токенов |
| `num_predict` | `4096` | От 512 до 8192 токенов |

Версия промпта — `e61-1.0`. Фиксированный seed не гарантирует совпадение ответов на другом оборудовании или версии Ollama. Имя модели не заменяет фиксацию digest весов.

## Этапы обработки

1. **Фрагменты.** Модель выделяет фрагменты, указывает существенность и объяснение. Цитаты сохраняются из исходного текста.
2. **Сущности.** Модель выделяет объекты, требования, запреты, условия, исключения и числовые значения. Элемент содержит цитату, вид и нормализованное значение.
3. **Связи и правила.** Модель формирует требования вида «ЕСЛИ → ТО» с ролями объектов a/b. Дубли и конфликтующие требования сохраняются для следующего этапа. Неизвестные понятия и неразобранные условия остаются в кандидате.
4. **Совместимость.** Сервер проверяет структуру, цитаты и отношения между кандидатами. Он возвращает дубли, доказанные конфликты, совместимые требования и случаи для ручной проверки.

| Порядок | Входы этапов |
|---|---|
| `filter_first` | Фрагменты полного текста → сущности существенных фрагментов → правила по фрагментам и сущностям → совместимость |
| `entities_first` | Сущности полного текста → фрагменты с учётом сущностей → правила по фрагментам и сущностям → совместимость |

При отсутствии существенных фрагментов этап построения правил пропускается. Фактически выполненные этапы сохраняются в `trace`.

## Проверка ответа

Каждый нейросетевой этап использует отдельную схему Pydantic: `Fragments`, `Entities`, `Candidates`. Ответ отклоняется при неверном JSON, лишних полях, неправильных типах, недопустимых значениях и незавершённой или обрезанной выдаче.

Цитаты фрагментов, сущностей и правил должны встречаться в исходном тексте после нормализации пробелов. Повторяющиеся ID кандидатов заменяются уникальными. Источник берётся из пользовательских метаданных. Отметка проверки нормативного источника сбрасывается в `false`.

Сервер задаёт `enabled: false` и статус `draft` или `needs_review`. Анализ не изменяет активную базу. Пользователь проверяет цитату, объекты, число, условия и источник, исправляет JSON и подтверждает правило отдельной операцией.

Проверка схемы и наличия цитаты не подтверждает правильность смысловой связи. Модель может неверно присоединить число или условие к объекту. Это проверяется при просмотре и оценивается экспериментально.

## Сравнение правил

Алгоритм сравнивает типы объектов, параметр, единицы, область, роли условий, исключения и неразобранные части. Метры, сантиметры и миллиметры приводятся к метрам. Для симметричной дистанции допускается обмен ролями с обменом соответствующих условий.

| Результат | Критерий |
|---|---|
| `duplicate` | Совпадают поддерживаемый контекст и требование |
| `conflict` | При одинаковом контексте пересечение допустимых числовых интервалов пусто |
| `compatible` | Требования при одинаковом контексте допускают общее значение |
| `review` | Пересечение контекстов или смысл требования не установлены алгоритмом |

Разные нижние границы, например синтетические `>= 4 м` и `>= 6 м`, совместимы. Синтетические `>= 8 м` и `<= 5 м` при одинаковом контексте несовместимы. Условия равенства одного атрибута разным значениям, например `material == wood` и `material == stone`, задают непересекающиеся области; такая пара не помечается конфликтом.

Другие различия условий без доказанного непересечения, пересекающиеся наборы типов, разные области и разные нормативные документы или редакции требуют ручной проверки. Алгоритм не определяет юридический приоритет документов и не решает произвольные логические выражения. Отношения сохраняются вместе с кандидатами.

## Сценарий оценки

Корпус [dataset.json](../evaluation/dataset.json) содержит десять синтетических текстов с эталонными правилами и отношениями. Числа не являются нормативными. Случаи включают расстояния, условия, исключения, запрет, несущественные фрагменты, дубли, противоречия и похожие совместимые правила.

Оба порядка запускаются на одинаковых текстах и одной модели с одинаковыми параметрами:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m evaluation.evaluate --model qwen2.5:3b --repeats 1 --seed 42 --temperature 0 --num-ctx 16384 --num-predict 4096
```

FastAPI-сервер для CLI не требуется. Сервис Ollama должен работать. Для предварительного запуска можно добавить `--cases T01 T02`. Параметр `--repeats 3` задаёт три повтора. Порядок конвейеров чередуется между повторами.

Для подготовки протокола без вызовов модели:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m evaluation.evaluate --prepare-only
```

Выходная папка по умолчанию — `evaluation/results`; параметр `--output` задаёт другую папку. Запуск с одинаковыми именами перезаписывает соответствующие файлы. Для разных экспериментов используются отдельные папки.

Протокол содержит имя и digest модели, версию Ollama, параметры, порядок, повторы, версию промпта, SHA-256 корпуса и сведения о среде выполнения. Записи этапов содержат ответы, длительности и количество токенов при наличии этих полей в ответе Ollama. Первый вызов может включать загрузку весов; это учитывается при интерпретации времени.

При недоступной модели записывается `not_run` без метрик. После обработанных запусков создаются записи по текстам и `comparison.md`. Ошибки отдельных запусков сохраняются. Сводка указывает число завершённых, ошибочных и запланированных запусков.

## Метрики

Используются `precision = TP / (TP + FP)`, `recall = TP / (TP + FN)`, `F1 = 2TP / (2TP + FP + FN)`.

| Объект оценки | Сопоставляемые данные |
|---|---|
| Сущности объектов | Множества нормализованных типов из этапа сущностей и эталонных правил |
| Значения | Типы, параметр, единица, область, оператор и число в метрах |
| Условия и исключения | Контекст, роль a/b, поле, оператор, значение и вид условия |
| Дубли и противоречия | Пары кандидатов после сопоставления с эталонными правилами |

Сводка использует micro-показатели по завершённым запускам. Пустой знаменатель даёт `null`. Ошибочные запуски учитываются в покрытии, но не включаются в метрики извлечения. Сравнение с неполным покрытием требует отдельного анализа. Случаи `review` подсчитываются отдельно и не считаются доказанными противоречиями.

Виды сущностей требований и запретов сохраняются в ответах, но отдельный F1 для них не рассчитывается. Корпус из десяти синтетических текстов не определяет качество на нормативных документах. Для завершения исследования необходимы запуски установленной модели, проверенные тексты, ручная разметка и анализ ошибок.
