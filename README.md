# Планировщик садового участка 2025_Е61

Локальный учебный проект: Python + FastAPI, HTML/CSS/JavaScript и SVG. Можно изменять форму своего и соседних участков, размещать объекты, рисовать коммуникации, измерять расстояния между контурами и проверять структурированные правила. Сохранение — JSON. Интернет и регистрация для работы планировщика не нужны.

**Все шесть встроенных правил и десять текстов для оценки синтетические. Их числа вымышлены для обучения и не являются действующими СНиП или СП.** Проверенная нормативная база в поставку не включена. Есть механизм ввода источника и подтверждения правил человеком.

В его командах замените `D:\идз` на путь к распакованной папке или пропустите `cd`, если PowerShell уже открыт в ней. После установки приложение запускается через `run.bat`.

## Быстрый запуск в исходной рабочей папке

Окружение `.venv` уже подготовлено при разработке. Пока сервер запущен, откройте <http://127.0.0.1:8000>. Для следующего запуска в PowerShell:

```powershell
cd 'D:\идз'
.\run.bat
```

Или дважды щёлкните `run.bat` в Проводнике. Окно запуска оставьте открытым. Остановка — `Ctrl+C`. Если адрес уже работает, второй сервер запускать не нужно.

## Установка на другом Windows-компьютере

1. Установите Python 3.12 с [официального сайта Python](https://www.python.org/downloads/windows/). В установщике включите Python Launcher; при необходимости отметьте добавление Python в PATH.
2. Распакуйте исходники в доступную для записи папку. Откройте PowerShell в этой папке.
3. Выполните команды ниже. Для первой установки зависимостей нужен интернет. Активация окружения не требуется, менять политику выполнения PowerShell не нужно.

```powershell
cd 'D:\идз'
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

4. Откройте в браузере <http://127.0.0.1:8000>. Сервер запускается только на вашем компьютере.

`requirements.txt` фиксирует три используемых пакета верхнего уровня. Для воспроизведения всех версий среды проверки вместо него установите `requirements-lock.txt`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

Если `py` не найден, проверьте установку Python. Если у вас `python --version` показывает Python 3.12, замените `py -3.12` на `python`. Если ошибка сообщает, что порт занят, откройте уже работающий адрес или остановите прежнее окно `Ctrl+C`. Для другого порта используйте `--port 8001` и адрес `http://127.0.0.1:8001`.

Созданное здесь окружение использует встроенный Python Codex. Переносить `.venv` на другой компьютер нельзя: создайте его заново описанными командами.

## Как работать с планом

1. Нажмите **«Открыть пример»**. В нём участок 30 × 40 м, два соседа, 12 объектов и четыре коммуникации.
2. Введите ширину и длину слева, нажмите **«Задать прямоугольник»**. Объекты сохранят координаты. Для произвольной формы включите **«Границы»**, выберите участок, перетаскивайте вершины. Координаты, добавление и удаление вершин также доступны справа. Двойной щелчок по выбранному ребру добавляет вершину. Самопересечения отклоняются.
3. Выберите участок для добавления. Нажмите тип объекта в каталоге, затем щёлкните на плане. Объект можно добавлять и соседям. Выберите его и перетащите. Справа можно поменять название, тип, принадлежность, центр X/Y, ширину/глубину и поворот. После изменения полей нажмите **«Применить изменения»**. Поворот положителен по часовой стрелке.
4. Заполните материал, высоту, герметичность и класс дерева, если они известны. Пустое поле означает «нет данных», а не соответствие правилу. Дополнительные характеристики вводятся как JSON в раскрывающемся блоке.
5. Для коммуникации выберите электричество, газ, канализацию или воду. Щёлкайте по точкам и нажмите **«Завершить линию»**. Выбранная линия имеет перетаскиваемые точки; справа можно менять их координаты и количество. Двойной щелчок по отрезку вставляет точку. `Esc` отменяет незавершённую линию.
6. **«Измерить»** + два щелчка измеряет расстояние между точками. Для объектов и границ используйте списки «От»/«До» справа. Измерение между объектами идёт между их контурами, с учётом поворота. Пересечение/вложение даёт 0 м. Граница измеряется как линия, поэтому расстояние до неё у объекта внутри участка положительное.
7. Нажмите **«Проверить план»**. Результаты содержат объекты, фактическую и требуемую дистанцию, условия, объяснение и источник. Нарушения красные, нехватка данных — жёлтая. **«Показать на плане»** возвращает к объекту и линии измерения.
8. **«Скачать план»** сохраняет JSON в загрузки браузера. **«Загрузить JSON»** восстанавливает его после серверной проверки. Удобная копия последнего плана хранится также в браузере; основной переносимый файл — скачанный JSON.

`Ctrl+Z`/`Ctrl+Y` или ↶/↷ отменяют и повторяют изменения плана. Колесо изменяет масштаб, `Shift` + перетаскивание сдвигает вид. **«Весь план»** возвращает все видимые участки в кадр. Свой участок удалить нельзя; соседний участок с его содержимым можно удалить после сообщения интерфейса.

Объекты имеют **прямоугольные расчётные контуры**. Для деревьев и кустов это условная проекция кроны. Коммуникации можно проводить за пределы участка; их строительные ограничения в этой версии не проверяются.

## Правила и источники

На вкладке **«База правил»** можно просмотреть/исправить JSON, проверить дубли и противоречия, подтвердить включение, выключить правило, скачать и импортировать базу. Редактирование правила с тем же ID обновляет его. Импорт заменяет базу на сервере, поэтому сначала скачайте нужную копию. План и база правил — отдельные файлы.

Поддерживаемые параметры: `distance`, `boundary_distance`, `height_m`; операторы `>=`, `>`, `<=`, `<`, `==`, `!=`; единицы `m`, `cm`, `mm` (и русские обозначения). Типы объектов и условия описаны в [документе об архитектуре](docs/ARCHITECTURE.md). Условия соединяются «И», исключения — «ИЛИ». Сложные условия надо разобрать вручную: `unresolved` препятствует активации.

Для нормативного правила заполните `source.kind = "normative"`, точное название документа, редакцию, пункт и ссылку. Сверьте цитату с оригиналом и применимость к задаче, исправьте кандидат, отметьте подтверждение человеком. Приложение проверяет заполненность этих полей; оно не подтверждает актуальность нормативного документа само.

## Нейросетевой анализ через Ollama

Модуль выполняет настоящие обращения к языковой модели, установленной на вашем компьютере. Регулярные выражения не заменяют извлечение. Планировщик работает и без модели, но кнопка анализа в этом случае честно сообщает о недоступности.

1. Установите Ollama с [официального сайта](https://ollama.com/download/windows). Это отдельная бесплатная программа; аккаунт приложению не нужен.
2. В PowerShell загрузите модель. Имя по умолчанию — `qwen2.5:3b`; можно использовать другое установленное имя. Загрузка весов требует интернета и свободного места, время анализа зависит от оборудования.

```powershell
ollama pull qwen2.5:3b
ollama list
```

3. Ollama должна быть запущена. Обычно после установки она работает в фоне. Если нет, выполните в отдельном окне:

```powershell
ollama serve
```

4. В **«Анализ текста»** укажите имя модели, нажмите **«Проверить модель»**, вставьте текст или загрузите TXT в UTF-8. Можно вставить синтетический пример из списка.
5. Выберите порядок этапов, заполните источник и нажмите **«Извлечь кандидаты нейросетью»**. На CPU обработка может занимать несколько минут. Ответы этапов доступны в раскрывающихся блоках.
6. Откройте кандидат, проверьте цитату, объекты, условия, число и источник. Только **«Подтвердить и включить»** после отметки просмотра меняет активную базу. Дубли и доказанные противоречия блокируют включение.

Используется `POST /api/chat` с JSON Schema, `stream: false`. Документация: [Ollama Chat API](https://docs.ollama.com/api/chat), [Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs), [карточка Qwen2.5](https://ollama.com/library/qwen2.5). Связь нейросетевых этапов и ограничения описаны в [NEURAL_METHOD.md](docs/NEURAL_METHOD.md).

При нестандартном локальном порте Ollama или медленном процессоре задайте переменные **до запуска сервера**:

```powershell
$env:OLLAMA_URL = 'http://127.0.0.1:11434'
$env:OLLAMA_TIMEOUT = '300'
.\run.bat
```

По умолчанию тайм-аут одного вызова — 180 секунд. Разрешены только локальные HTTP-адреса Ollama. Тексты до 18 000 символов, контекст по умолчанию 16 384 токена, ответ до 4096 токенов. Если ответ обрезан, уменьшите текст или увеличьте предел ответа/контекста в пределах интерфейса. Не каждый выбор модели обеспечит хорошую точность; её надо измерять на корпусе.

## Проверки и воспроизводимая оценка

Автоматические тесты не требуют дополнительных пакетов или запущенной модели:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

Проверка реального HTTP-сервера (сервер должен работать в другом окне):

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\smoke_api.py
```

Нейросетевое сравнение обоих порядков на 10 синтетических текстах:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m evaluation.evaluate --model qwen2.5:3b --repeats 1 --seed 42 --temperature 0 --num-ctx 16384 --num-predict 4096
```

Для предварительной проверки на двух текстах добавьте `--cases T01 T02`. Для подготовки протокола без модели используйте `--prepare-only`. При недоступной модели сценарий создаёт `status.json` со статусом `not_run`, без выдуманных метрик. Успешные вызовы дают ответы этапов, digest модели, параметры, показатели precision/recall/F1, время и `comparison.md`. Подробнее: [evaluation/README.md](evaluation/README.md).

Фактически проверено при разработке: **54 автоматических теста**, HTTP-сценарии и основные операции в браузере. Исходный пример: **2 нарушения, 15 соответствий, 2 случая нехватки данных**. Полный перечень — [docs/VERIFICATION.md](docs/VERIFICATION.md).

**Нейросетевой эксперимент ещё не выполнен: Ollama/модель недоступны в среде разработки.** Тестовые заглушки используются только в модульных тестах транспорта и не считаются результатами извлечения.
